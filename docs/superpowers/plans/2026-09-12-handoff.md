The seven foundation gaps are closed:

1. Split panes: a layout tree of panes with *Split right* and *Split down*
   in the palette, draggable dividers, a shared buffer per note, and
   `workspace.json` storing `{layout, activePane}`. The old `{tabs, active}`
   still opens as one pane.
2. Attachments open in a tab: images and PDFs through the asset protocol,
   scoped to the vault at runtime; every file offers *Open in default app*.
3. A corrupt index is deleted and rebuilt with a notice; only corruption
   deletes, never a locked file. Watcher failures are reported and the UI
   rescans on window focus.
4. `[[Note#^id]]` is a block link. Block ids are indexed, rename keeps
   them, links jump to headings and blocks in live and reading mode, block
   ids are muted in live preview and hidden in reading view, and a backlink
   opens at the mentioning line.
5. Tests for command serialisation, editor decorations and the palette.
6. Opening ten thousand notes, release build: first open 2.1 s, second
   0.1 s, one save 0.16 s. Before this plan the second open and every save
   took 11 s, because link resolution scanned `links` once per target.
   Run: `cargo test --release -p engram-notes-core --test open_time -- --ignored --nocapture`.
7. Properties are edited by type: list chips, checkbox, number, date,
   date-time, text, and a remove button per property.

Deferred to the graph-and-bases plan, unchanged: folder rename and delete,
image embeds inside notes, inline rename in the explorer.

## User preferences learned

- KISS. Comments short, as `AGENTS.md` says.
- Where Obsidian inspired a feature, match Obsidian's behaviour and file
  formats. Do not reinvent.
- Visual and editing quality at least Obsidian's, whatever it costs.
- Engram is a source of concepts, not a dependency. Self-grading stays out
  of the local app.
- Air-gapped machines matter: the embedding model must be loadable from a
  directory as well as downloaded.
- Plans are executed inline. Merges are local fast-forwards when the user
  says so; ask each time.
- Verify UI changes in the running app before calling anything done.

## Gotchas found the hard way

- The core library is `engram_core`. A crate named `core` shadows Rust's own
  and breaks doctests.
- Run the Tauri CLI from the repository root. `pnpm tauri <cmd>` inside `ui`
  does that. `pnpm dev` must run inside `ui`; from the root it fails with
  "Command dev not found".
- Fedora needs `webkit2gtk4.1-devel gtk3-devel libsoup3-devel
  librsvg2-devel libappindicator-gtk3-devel dbus-devel glib2-devel`. Check
  with `pkg-config --modversion glib-2.0` before building `src-tauri`.
- markdown-it 15 ships its own types. `@types/markdown-it` conflicts with
  them; leave it out.
- TypeScript stays on 5.x; svelte-check does not accept 7.
- After adding a CodeMirror package, restart Vite with `pnpm dev --force`.
- Svelte warns when a component mutates state passed as a prop. Components
  read tabs and buffers from the store by pane id and path, and change them
  through store methods.
- `Index::rebuild` and `update_file` call `resolve_all`; keep
  `links_target_raw` indexed or every save scans the links table per target.
- `pkill -f` with a pattern that also appears later in the same shell
  command kills that shell. Use `pkill -x <name>`.

## Checking the app

Desktop screenshots fail on the user's KDE Wayland session this time:
`spectacle` captures an image it cannot save and hangs, with or without the
sandbox, and `import` cannot capture either. What worked instead:

1. `cd ui && pnpm dev` in the background.
2. Write a fixture like `ui/scripts/fixture.example.json`: `root`, `config`,
   `files` (path and text, or path and size for attachments), `workspace`,
   and optionally `properties`, `anchors`, `backlinks`, `outgoing`.
3. `node ui/scripts/shot.mjs <fixture> <out.png> [width] [height]` prints a
   DOM summary and console errors and saves a screenshot. Playwright's
   cached Chromium is the default browser; set `CHROME` otherwise. `EVAL`
   runs an expression first, for clicks, palette input or CodeMirror edits
   (`import("/node_modules/.vite/deps/@codemirror_view.js")` gives
   `EditorView.findFromDOM`); invoked commands are in `window.__calls`.
4. For backend behaviour, run `target/debug/engram-notes <vault>` and
   inspect the index at `~/.local/share/engram-notes/vaults/<first 16 hex
   of sha256(vault path)>/index.db`.
5. If `spectacle -b -n -f -o shot.png` works again, prefer the real window.
