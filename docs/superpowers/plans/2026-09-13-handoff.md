## What the graph-and-bases plan built

- **Moves**: renaming or dragging a file, an attachment or a folder moves
  every file below it and rewrites wikilinks, embeds and markdown links that
  named them. The index is rebuilt once after a move rather than updated per
  file. `core/src/rename.rs`.
- **Explorer**: inline rename, a folder menu (new note, new folder, new base,
  rename, delete), drag to move onto folders or the root, empty folders via
  `list_folders`. The window sets `dragDropEnabled: false` so HTML drag and
  drop reaches the webview.
- **Image embeds**: `![[pic.png|300]]`, `|300x200` and `![alt|120](path)` in
  live preview and reading view, resolved like Obsidian (exact path, then
  name, shortest path). Links to a `.base` or an attachment open the file.
- **Graph**: `core/src/graph.rs` builds nodes (notes, attachments, unresolved
  targets) and one edge per linked pair; attachments resolve by path or name.
  `ui/src/lib/graph.ts` holds Obsidian's `graph.json` keys and defaults, the
  `tag:`/`path:`/`file:` search operators (plain words also match full-text
  hits), tag nodes, orphans and the local neighbourhood. `GraphView.svelte` is
  a canvas over `d3-force`, batched per colour. Tabs use the pseudo-paths
  `graph:global` and `graph:local`; Obsidian forbids `:` in names. Force
  factors were tuned by eye: charge −20 per repel unit, link distance / 5,
  centre × 0.1, labels fade in from zoom 0.8.
- **Bases**: `core/src/bases/` has the expression parser (`expr.rs`), the
  evaluator (`eval.rs`, dates and Obsidian duration units) and the runner
  (`mod.rs`: filters, formulas, columns, sort, limit, `set_sort`). Decisions
  checked against Obsidian's help: `file.tags` values carry `#`,
  `file.hasTag` matches nested tags, `file.inFolder` includes sub-folders,
  `sort` is a list of `property` and `direction: ASC|DESC`. Chosen where
  Obsidian's docs are silent: the root folder is `/`, `not` holds when none of
  its filters do, rows are notes only. Unsupported functions, fields, view
  types, `groupBy` and `summaries` are listed in the view; a filter that fails
  to parse yields no rows. `BaseView.svelte` has a view picker, header click
  to sort (written back to the file), typed cell editors shared with the
  properties pane (`PropertyValue.svelte`) and a YAML source mode.
- **Dark theme in WebKitGTK**: `color-scheme` per theme, a drawn `<select>`,
  no spinners on number inputs, rings only on keyboard focus, and the text
  font on CodeMirror's scroller.

## Notes for the next plan

### fastembed, checked 2026-09-13

- `fastembed = { version = "6.1", default-features = false, features =
  ["ort-download-binaries-rustls-tls", "hf-hub-rustls-tls"] }` builds and links
  on this machine (probe: 26 s). ort `=2.0.0-rc.13` downloads onnxruntime at
  build time. rustls avoids OpenSSL development packages locally and in CI.
- `TextEmbedding::try_new(TextInitOptions::new(EmbeddingModel::MultilingualE5Small).with_cache_dir(dir).with_show_download_progress(false))`.
  `embed` takes `&mut self`, so the `Embedder` trait takes `&mut self` or
  wraps the model in a mutex.
- `MultilingualE5Small` is `intfloat/multilingual-e5-small`,
  `onnx/model.onnx`, 384 dimensions, mean pooling. fastembed has no quantized
  e5-small, although the spec asks for one: either accept the unquantized
  model and note it, or load a quantized ONNX as a user-defined model.
- fastembed adds no e5 prefixes. Prepend `query: ` and `passage: `.
- The offline *model directory*: `TextEmbedding::try_new_from_user_defined(model, InitOptionsUserDefined::new())`
  with `UserDefinedEmbeddingModel { onnx_file, external_initializers,
  tokenizer_files: TokenizerFiles { tokenizer_file, config_file,
  special_tokens_map_file, tokenizer_config_file }, pooling:
  Some(Pooling::Mean), quantization: QuantizationMode::None, output_key: None }`,
  the bytes read from `model.onnx`, `tokenizer.json`, `config.json`,
  `special_tokens_map.json` and `tokenizer_config.json`. Check for a
  constructor with builders (`with_pooling`, `with_quantization` exist) in
  case the struct is not built by literal.
- Download progress is printed, not reported through a callback, so the
  status bar can say *downloading model*, not a percentage.
- Suggested: `FastEmbedder` in `core` behind a cargo feature that `src-tauri`
  enables, so `cargo test -p engram-notes-core` needs no model and no
  network; `FakeEmbedder` always compiled.

### engram's concepts, from `../engram` on `feat/observations`

- **Decay** (`src/store/links.rs`): `decayed(w, stamped_at, now, half_life_days)
  = w · 2^(−elapsed / half_life)`, elapsed floored at zero, a half-life ≤ 0
  turns decay off. A bump reads the row, decays it to now, adds the delta and
  writes it with the new stamp, in one immediate transaction. Pairs are
  stored with `a < b`.
- **Associations**: one co-appearance adds 1; shown above a decayed 2.0;
  pruned below 0.5; cues are normalised queries (lowercase, whitespace
  collapsed), the three most frequent kept. engram's half-life is 30 days;
  the spec's 90 days for `assoc` wins.
- **Activation**: the same read, decay, add. engram subtracts a decayed
  baseline; in engram-notes activation starts with no row, so there is none.
- **Divider** (`src/core/search.rs`, `cliff`): over scores sorted descending,
  at least three, the largest gap must exceed 3.0 × the mean of the other gaps
  and 0.01 × the top score; everything from there is marked. It reads cosine
  similarity, never the fused RRF score, whose first gap is structurally the
  largest. The spec says "a fraction of the top score"; AGENTS.md says to
  match engram's concepts, so use the cliff and record the deviation.
- **Fusion**: RRF with k = 60; `candidate_multiplier` 3.
- **Priming** (`prime`): by rank. Rows 0 and 1 never move. Activation is
  normalised within the list (divided by its maximum). A row climbs past its
  predecessors, nearest first, while it beats each by more than a margin of
  0.5, at most `lift` places, never above index 1. Every climb is decided
  against the original order in one pass, then one stable sort by (target,
  not climbed, index); only rows that climbed are flagged. The spec adds that
  only hits above the list's median activation may climb, with a lift of 2.
- **Spread** (`associated`): anchors are the top 3 hits; their links above
  the show threshold, strongest first, skipping notes already listed, at most
  `spread_max` (3), one hop, never reordering.
- **Sitting**: working memory ended by an idle gap (engram's tests use 900 s;
  the spec says thirty minutes).

### Design sketch, not yet a plan

- Schema version 3 adds `passages(path, ordinal, heading, line, text, hash)`
  with `ON DELETE CASCADE`; `vectors` keyed by passage text hash, so unchanged
  passages and renamed notes keep theirs, with the model id in `meta` and
  vectors cleared when it changes; `activation(path, value, stamped_at)`;
  `assoc(a_path < b_path, value, stamped_at, queries)`; `events(at, kind, path,
  query, sitting)`. A rename moves `activation` and `assoc` rows. A schema bump
  drops memory with the rest of the index; the spec accepts that, say so.
- Passages: the body split on headings, then paragraphs, at most about 1 200
  characters, the heading path prepended.
- `src-tauri`: an embed thread taking batches of 32, paused while the user
  types (the editor pings), emitting the pending count and model state.
- Commands: hybrid search; record an event (open, open from search, follow a
  link, search); related for a note (associated, similar, suggested links);
  forget memory; embed status; semantic edges for the graph (associations and
  top-k similar notes, dashed and weighted, off in the global graph and on in
  the local one).
- UI: the search pane draws the divider and shows loose hits smaller, with an
  associated band under the list; a Related pane whose *link* action inserts
  `[[Title]]` at the cursor (the editor needs an insert hook); the status bar
  shows the queue and the memory toggle; a palette command picks the model
  folder and writes `app.json`.

## Gotchas found the hard way

- The core library is `engram_core`. A crate named `core` shadows Rust's own
  and breaks doctests.
- Run the Tauri CLI through `pnpm tauri <cmd>` inside `ui`. From the
  repository root it fails with "Command tauri not found", and piped through
  `tail` the command still exits 0: check the binary's timestamp.
- `pnpm tauri build --debug --no-bundle` embeds `ui/dist`, so the real window
  shows a frontend change only after a rebuild.
- `pnpm dev` must run inside `ui`. A Vite server from an earlier session may
  already hold port 5173 and serve this repository; reuse it.
- Fedora needs `webkit2gtk4.1-devel gtk3-devel libsoup3-devel
  librsvg2-devel libappindicator-gtk3-devel dbus-devel glib2-devel`. Check
  with `pkg-config --modversion glib-2.0` (2.88.3 here).
- markdown-it 15 ships its own types; leave `@types/markdown-it` out.
  `Token.attrGet` returns `string | number | null`, and a renderer `env` must
  be a type alias, because interfaces lack the index signature `Env` needs.
- TypeScript stays on 5.x; svelte-check does not accept 7.
- After adding a CodeMirror or other npm package, restart Vite with
  `pnpm dev --force` if imports fail.
- Svelte warns when a component mutates state passed as a prop. Components
  read tabs and buffers from the store and change them through its methods.
- `Index::rebuild` and `update_file` call `resolve_all`; keep
  `links_target_raw` indexed.
- `pkill -f` with a pattern that also appears later in the same shell
  command kills that shell. Use `pkill -x <name>` or a pid.
- A Rust raw string `r#"…"#` ends at the first `"#`, so `"#tag"` inside needs
  `r##"…"##`.
- WebKitGTK paints a native `<select>` and number spinners light in either
  theme and rings buttons after a mouse click. Headless Chromium does not show
  either. CodeMirror's base theme puts a monospace font on `.cm-scroller`;
  headless showed that too, and it was wrongly taken for a font fallback.
- Tauri's file-drop handler swallows HTML drag and drop unless the window
  sets `dragDropEnabled: false`.

## Checking the app

Desktop screenshots still fail on the user's KDE Wayland session: `spectacle
-b -n -f -o <file>` exits 0 and writes nothing, sandboxed or not. What works:

1. `cd ui && pnpm dev` in the background, or reuse a running server on 5173.
2. Write a fixture like `ui/scripts/fixture.example.json`: `root`, `config`
   (set `theme` to `dark` to check the dark theme), `files` (path and text, or
   path and size), `workspace`, and optionally `folders`, `properties`,
   `anchors`, `backlinks`, `outgoing`, `graph`, `graphConfig`, `bases` (a
   table per base path), `affected` (for rename plans) and `search`.
3. `node ui/scripts/shot.mjs <fixture> <out.png> [width] [height]` prints a
   DOM summary and console errors and saves a screenshot. `SETTLE` waits
   longer (graphs need about 5000 ms); `EVAL` runs an expression first, for
   clicks, context menus, drag events with a `DataTransfer`, or CodeMirror
   edits (`import("/node_modules/.vite/deps/@codemirror_view.js")` gives
   `EditorView.findFromDOM`). Invoked commands are in `window.__calls`. For
   graph hover, sweep `pointermove` until the canvas cursor is `pointer`.
4. For the real window: `cd ui && pnpm tauri build --debug --no-bundle`, run
   `target/debug/engram-notes <vault>` outside the sandbox, and ask the user
   for screenshots. A small demo vault with folders, a PNG, links, an
   unresolved link and a `.base` with two views and one unsupported view makes
   the review quick.
5. For backend behaviour, inspect the index at
   `~/.local/share/engram-notes/vaults/<first 16 hex of sha256(vault
   path)>/index.db`.
