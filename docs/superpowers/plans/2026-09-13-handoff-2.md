## What this session built

### Semantic search and memory (on `master`)

Schema version 3 adds `passages`, `vectors`, `activation`, `assoc` and `events`.
`core/src/search/` holds passage splitting, a brute-force cosine scan, RRF and
the divider; `core/src/memory/` holds decay, events in sittings, activation,
associations, priming, spread and the Related pane's three groups;
`core/src/embed/` holds the `Embedder` trait, a deterministic fake and
fastembed behind the non-default `fastembed` feature that `src-tauri` enables.
`src-tauri/src/embed.rs` runs one thread that loads the model and drains the
queue, paused while the user types.

**`docs/memory.md` is the record of the numbers and of every departure from the
spec.** Read it before touching search or memory. The three that matter:

1. The divider is engram's cliff, not a fraction of the top score.
2. The model is unquantized — fastembed 6.1 ships no quantized e5-small.
3. **A similarity floor was added that the spec does not mention**, because
   without one every note is similar to every note. This was found in the real
   window, not in tests: e5-small puts all 45 note pairs of the demo vault
   between 0.755 and 0.891, so an unrelated pair still scores 0.755. The floor
   is 0.83, a hard cut in the Related pane and on semantic graph edges, and in
   search the divider is the later of the cliff and the floor. A relative band
   on top of it was tried and dropped: over the same pairs it only ever deleted
   real neighbours. **The number belongs to `multilingual-e5-small`; a model
   loaded from a folder will want a different one.** It is
   `search.similarity_floor` in `app.json` and in the settings dialog.

### Obsidian parity, first pass (on `feat/obsidian-parity-ui`)

Interface density, graph style (small pale nodes, labels gated on zoom), the
pane taking over scrolling from CodeMirror, the properties block in the note's
flow, a history per tab with back and forward, the tab header, the `+` tab, the
left ribbon, `all_properties` with counts, switchable right-sidebar views, a
fuller status bar, and a settings dialog.

Then the user put it beside Obsidian and it was clearly worse. The second pass
fixed the icons (`@lucide/svelte`, the set Obsidian itself uses), the tab bar
(34px, rounded active tab, close only on the active or hovered tab) and the
density, which **the first pass had made smaller and tighter than Obsidian
itself** — the handoff's phrase "smaller interface text, tighter rows" was
followed without measuring the thing being copied. Base is 14px/1.5, nav and
tabs 13px, rows 4px.

## Next steps, in order

1. **Finish Obsidian parity.** The user has seen the current build side by side
   and asked for all three of these:
   - **A full-width tab bar.** Obsidian's spans the whole window with the
     sidebars beneath it; ours sits above the centre pane only. This is a
     `.layout` grid change: a tab-bar row above the three columns, with the
     tab strip lifted out of `Pane.svelte`. Watch out for the split layout —
     each pane still needs its own strip when panes are split, so the full-width
     bar probably belongs to the top-level pane only, with split panes keeping
     theirs. Decide this before writing the plan.
   - **The properties block's label and type icons.** Obsidian heads the block
     *Properties* and puts a Lucide icon on each row by value type: `text` for a
     string, `tag` for a list of tags, `hash` for a number, `calendar` for a
     date, `check-square`-like for a checkbox. `value_type` already comes from
     the index (`core/src/index/rebuild.rs`, `value_type()`), but the frontend
     currently reads raw JSON values through `api.properties`; either infer the
     type in `ui/src/lib/properties.ts` or return the type with the value.
   - **Explorer folder chevrons and file icons.** Obsidian shows a chevron on
     folders and a file icon on notes. `ui/src/components/Explorer.svelte`
     renders bare text today. Lucide is already a dependency.
2. **Then ask the user whether to merge `feat/obsidian-parity-ui` locally, open
   a pull request, or keep it.** They merged the last branch locally.
3. The roadmap items, each needing its own spec first.

## How the user works

- KISS, and comments short, as `AGENTS.md` says.
- Where a feature is Obsidian's, **match Obsidian by measuring it, not by
  impression** — the density mistake above came from doing the latter.
- Visual and editing quality at least Obsidian's, whatever it costs. The user
  compares the two side by side and will say plainly when ours is worse.
- engram is a source of concepts, not a dependency.
- Air-gapped machines matter: the model must load from a folder.
- Plans are written with superpowers:writing-plans and executed inline with
  superpowers:executing-plans, on a branch off `master`.
- **Tell the user before a plan departs from the spec**, and record the
  departure in the docs.
- Verify every UI change with `shot.mjs` before calling it done, then ask the
  user for screenshots of the real window and review them together. The
  headless check catches layout and wiring; it did **not** catch either of this
  session's two real defects — the missing similarity floor and the overshot
  density. Both needed the user's eyes on the real window.
- When the session ends, commit and push what exists and write the handoff.

## Checking the app

Unchanged from the previous handoff, and still the only way that works — the
user's KDE Wayland session cannot take desktop screenshots.

1. `cd ui && pnpm dev` in the background, or reuse a server already on 5173.
2. Write a fixture (see `ui/scripts/fixture.example.json`). Keys the stub
   understands now also include `search` (a `SearchResults` object), `related`,
   `semanticEdges`, `embed`, `allProperties`, and `rightPane` inside
   `workspace`. **A fixture's `config` must carry the `search`, `memory` and
   `embed` sections** or fields bound to them render empty — that bit the
   settings dialog's *Similarity floor* during this session.
3. `node ui/scripts/shot.mjs <fixture> <out.png> [w] [h]`, with `SETTLE` for
   graphs (5000 ms) and `EVAL` to click, type or scroll first. Read the PNG;
   the DOM summary alone proves nothing about how it looks.
4. Real window: `cd ui && pnpm tauri build --debug --no-bundle`, then
   `target/debug/engram-notes ~/engram-demo-vault` outside the sandbox. That
   demo vault exists, with Rust, Kitchen and Daily folders, links, an unresolved
   `[[Async Rust]]` and enough text on two subjects for semantic search to have
   something to find.
5. The index is at
   `~/.local/share/engram-notes/vaults/<first 16 hex of sha256(vault path)>/index.db`;
   for the demo vault that is `ea1238f6934152b7`. Reading the `vectors` blobs
   out of it with a short Python script is how the similarity floor was
   measured, and is the right move whenever a number needs choosing rather than
   guessing.

## Gotchas added this session

- A Svelte component that takes props must not also declare a local `let props`
  — the compiler reads `$props()` as a store reference to it.
- CodeMirror keeps virtualising under `height: auto` inside a scrolling
  ancestor: 33 of 5001 lines rendered on a 162 000-pixel note. The worry that
  the pane taking over scrolling would cost virtualisation was unfounded.
- `lucide-svelte` is deprecated; the maintained package is `@lucide/svelte`.
- An `f32` widens on the way through JSON: 0.8 arrives as 0.800000011920929, so
  a serialisation test must compare with a tolerance.
- `grep` on a large UTF-8 markdown file silently found nothing in this
  environment's locale; `grep -a` worked. Worth remembering when a search comes
  back empty against expectation.
- The fastembed build makes CI's Rust job about a minute slower; `ort` fetches
  onnxruntime at build time over rustls, which needs no OpenSSL package.
